## Draft protocol decisions (new wire design, not new world facts)

All nine schemas use JSON Schema draft 2020-12, under `schemas/janseon/release-payload/v1/`. `$id` URIs at `https://schemas.seoul-dengoku.example/map-payload/v1/` are identifiers resolved from the checked-in registry, **never network endpoints**. Their versioned filenames and root `schema` constants are the proposed API. Every record has a closed field allowlist; additional properties fail. Required keys may not disappear. Arrays preserve source order unless the rules below explicitly sort them. No string normalization of source IDs is allowed.

Every member root is exactly `{schema,binding,origins,data}`. `schema` is the filename-specific `janseon-<wiki|game>-<kind>.v1` constant. `binding` is exactly `{mapSemanticSha256,identitySnapshotSha256,editions}`. Each edition is `{domain,datasetId,editionId,semanticSha256}`; each origin is `{editionRef,sourceSemanticSha256,sourceReceipt:{contentId,sha256}}`. These are protocol wrappers over existing store/manifest identities, not caller permission to self-author receipts. R/P and DB bytes stay in the release manifest/provenance, not payloads, avoiding circular hashes. All members of one release must agree on the complete binding. Origins cover the actual member dependencies; the later validator must compare them with the manifest and independently verified source rows.

There is no import actor/reason, absolute file path, approval body, private profile, legal adjudication or narrative summary in these DTOs. Content IDs are references to independently resolved approved evidence, not source discovery instructions. Schemas describe format; approval and public-visibility allowlists remain separate prerequisites.

### Coordinates and edition separation

- **Release geographic vector facts use OGC:CRS84 longitude/latitude**, never W SVG pixels or silently projected EPSG:5179. Points are exactly `[longitude,latitude]`, numeric bounds [-180,180]/[-90,90]. Graph named lat/lon convert explicitly to this location record; source values and source binding remain retained by M. No nearest-feature or geometry-derived movement is permitted.
- Observed rings/polygons preserve order, holes and original precision. Ring closure, nonzero area and join closure require later semantic validation; JSON Schema alone cannot compare first/last points or enforce foreign keys.
- Authored overlay geometry preserves the existing CRS84 contract; null location/footprint means explicitly no authored value, not missing evidence or permission to use an arbitrary fallback. geographicParentRef is not political parent or liege.
- SGIS426, legacy atlas427, graph334/409 and physical rail remain separate dataset/edition namespaces. This v1 proposal only defines available geometry from the implemented observed-geography domain. Legacy-atlas transport is **UNSET-5**, not automatically converted to observed data.
- Raster assets retain native CRS/axis/sample/nodata semantics rather than converting raster metadata to CRS84; their complete publication lane is **UNSET-4**. There is no raster `available` branch yet.

### Stable keys, not array indices

Entity refs are exactly `(datasetId,editionId,entityKind,sourceId)` and retain source strings. Stations use source station IDs; authored facilities/settlements use existing explicit authored refs; aliases explicitly target a station ref. Do not use names, positions, ORBAT IDs or nearest matches as keys.

**Proposed edge-wire identity:** in a graph dataset/edition, `entityKind=graph-edge`, `sourceId="edge-sha256:" + SHA256(canonicalEncode([minEndpointSourceId,maxEndpointSourceId]))`, using ordinal string comparison without Unicode normalization. Existing graph validation rejects duplicate unordered endpoint pairs and self-edges, so this is collision-checked and unique for that edition. The record additionally retains `sourceLocator` `/edges/<original ordinal>` for provenance only. It is not the wire key. A later adapter maps ledger `baseEdgeRef` historical locators through that exact edition's graph to this wire key. Authored edge-change refs remain their original explicitly authored keys. Reordering arrays does not change endpoint-derived edge keys; a new edition remains a different full identity. No global cross-edition identity is inferred. This algorithm is a design proposal for owner approval, not a claim that SQL currently uses it.

An edge record is exactly `{ref,a,b,sourceLocator}`; a/b are full station refs. Unknown/duplicate/dangling references fail later semantic acceptance. Underground links must name the stable edge ref. W creates `admitted edge ref -> output index` only when reconstructing its current final public output; it must not consult old output indices as ongoing authority. Full source-backed physical links are still UNSET-3, so the schema does not accept an invented `edge` index or graph-only path fallback.

### Null, absence, UNSET and semantic requirements

- Assignment valueRef null = explicit unplaced/unclaimed/cleared. Missing valueRef is malformed. No command/slot = unchanged or not authored, never implicit null. Unknown identity is not null. See command validator, not a new ownership rule.
- Crosswalk facilityRef null is an explicit authored clearing; missing is invalid. Edge a/b must both be null only for an explicit removal of a referenced base edge; future semantic validator must enforce this and roles/cycles/tombstone closure.
- Tombstones retain identity, forbid reuse and cannot strand references. Baseline restore is an operation, not an extra payload status.
- `unavailable` with an UNSET decision is legal draft transport, **not production acceptance**. Required consumers must fail rather than synthesize source facts. No fake data sentinel is inserted into numeric fields. Entire unresolved `available` record shapes remain unrepresentable until approved.
- `absent` is distinct from unavailable and explicit null. Schema shape does not authorize the coverage receipt. A denied/missing blob is never absent.
- Future semantic checks must verify unique IDs, cross-member binding equality, edition roles, row/receipt derivation, canonical hashes, identity affiliation status, coordinates/ring closure and exact source coverage. JSON Schema structural validity is necessary but insufficient. The existing ledger/source validators remain authoritative.

## UNSET owner decision list (genuine remainder)

1. **UNSET-1: authored projection identity.** Ledger hashes/refs currently use ordinal graph locators. Approve a new wire projection hash distinct from the retained ledger semantic hash and its exact sourceReceipt binding, or change the source identity contract first. This draft retains `semanticSha256` as the source authored hash; it must not be recomputed over transformed wire rows and called the same identity. No builder transformation is implemented here.
2. **UNSET-2: baseline station/facility crosswalk authority and coverage.** Choose the actual typed baseline source/edition, stable external facility IDs and an independently approved coverage statement. The command ledger supplies authored changes but not a complete baseline. Do not infer from station names, ordinals or missing changes.
3. **UNSET-3: physical rail and underground source registration.** Choose original raw CRS/axis and conversion evidence, stable path IDs, explicit path-to-edge/station mappings and approval, depth vertical datum/units and neutral/schematic handling. Existing W rail projected points and baked pixel paths do not determine a lossless CRS84 source record or a verified complete match. Required raw geometry may not fall back to graph straight lines; do not promote nearest-edge authoring heuristic into runtime authority. After this decision, a separately approved schema revision can add `available` records grounded in the fields enumerated above.
4. **UNSET-4: available terrain/roads/buildings lane.** Approve each dataset encoding, member/asset records, native CRS/axis/sample/nodata/date/license/attribution fields, coverage/absence receipt and immutable content resolver. G's retained GeoTIFF/PBF/MVT archive demonstrates real heterogeneous sources, not permission to invent one uniform asset DTO or claim no content exists. Only absence-with-proof and unavailable are specified now.
5. **UNSET-5: legacy atlas/population/landmark/CIA-overlay field disposition.** W preparation section 6.4 explicitly identifies these incomplete ownership/consumer mappings. Decide which source facts require additional release fields/members versus remaining W joins, preserving 426/427 editions. This draft does not put population/prose or historical holder state into the observed schema.
6. **UNSET-6: line/opening/source evidence projection.** The graph source retains replacement/exclusion/hub chronology evidence, whereas W also consumes regular-line adjacency, official line metadata/corrections and control ledgers. Approve the explicit source-backed transport for facts not in current graph/observed/authored M stores, and determine which graph evidence is redistributable versus retained via protected receipt. A hash receipt alone does not make these fields available to W/G consumers.

Approve the supported v1 wire choices and decide these six items (or keep the affected required capabilities blocked). Do not treat this document as approving publication. W operator lock/content-index and private generation receipt schemas remain task-9-specific decisions, not additional payload keys smuggled into this contract.
